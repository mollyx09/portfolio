Distributed RAG Indexer

A multi-phase Retrieval-Augmented Generation (RAG) indexing system implemented using Hadoop MapReduce, Apache Spark, and Apache Flink to support scalable semantic search and knowledge graph construction.

View Implementation

Project Overview

Situation: Modern Retrieval-Augmented Generation (RAG) systems require scalable indexing pipelines that can process large document corpora while supporting semantic search, graph-based reasoning, and incremental updates. Traditional single-stage pipelines struggle with cost efficiency, latency, and real-time adaptability at scale.

Task: Design and implement a production-style distributed indexing system capable of processing 600+ MSR research papers, supporting batch, micro-batch, and streaming ingestion models, and serving structured retrieval for downstream RAG-based question answering.

Action: Architected the system as a progressive distributed pipeline: implemented batch indexing using Hadoop MapReduce on AWS EMR, re-designed the pipeline using Apache Spark with Delta Lake for incremental processing and cost-efficient deduplication, and extended the system with Apache Flink on AWS EKS to support real-time streaming updates and Neo4j-based knowledge graph construction. Deployed the system on Kubernetes with IAM-secured access, EBS-backed persistence, and exposed retrieval and QA services via Akka HTTP REST APIs.

Result: Achieved an 85% reduction in batch processing time in the MapReduce implementation, a 70% reduction in compute and storage costs through content-hash deduplication in Spark, and sub-second P95 query latency with <2s end-to-end QA latency (search → retrieve → generate) in the Flink-based streaming system. Validated performance through sustained-load testing and end-to-end demos.
