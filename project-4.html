Empirical Study: Single vs. Multi-Agent LLM Systems

A rigorous empirical comparison of single-agent and multi-agent LLM pipeline architectures for automated code generation and requirements engineering, benchmarked across 1,282+ tasks on five industry-standard datasets.

View Implementation

Project Overview

Situation: The rapid adoption of LLM-based coding assistants has created a pressing question for production teams: when does the added complexity of multi-agent orchestration actually outperform a well-engineered single-agent system? Existing literature lacks controlled, cost-aware comparisons across standardized benchmarks, making it difficult to derive practical deployment guidelines.

Task: Design and execute a rigorous empirical study comparing single-agent and multi-agent LLM architectures for two core software engineering tasks — automated code generation and requirements engineering — while measuring not just accuracy but also token cost, repair iterations, and semantic correctness.

Action: Architected 3 LLM pipeline systems using LangGraph and LangChain, powered by Claude Sonnet (Anthropic API). Engineered 6 specialized agents — Planner, Extractor, Critic, Coder, Test Runner, and SME Advisory — with budget-guard constraints to prevent runaway token usage. Evaluated all systems across 1,282+ tasks on five datasets: HumanEval+, MBPP+, BigCodeBench-Hard, PURE, and NICE. Measured pass@1, Semantic F1, token cost per task, and repair iterations to derive actionable cost-efficiency guidelines.

Result: Achieved 100% pass@1 on HumanEval+ and MBPP+ and 0.781 Semantic F1 on requirements engineering tasks (PURE/NICE datasets). Derived concrete cost-efficiency deployment guidelines for production LLM systems, showing that multi-agent architectures provide measurable gains on complex, ambiguous tasks while single-agent pipelines remain competitive on well-defined coding benchmarks. Study ongoing as part of UIC coursework (January 2026 – Present).
